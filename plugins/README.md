# Python-плагины Calamus

Формат — `.plug`: ZIP с `manifest.json`, `main.py` и ресурсами. API 1, 2 и 3 поддерживаются. CPython 3.11.17 и необходимые стандартные модули встроены в APK Calamus. Chaquopy Java runtime и внешний модуль Calamus Python Isolation больше не используются.

## Изоляция по умолчанию

Изоляция обязательна для каждого плагина. Отдельные приложения, установка модуля и включение переключателя не нужны. Android автоматически запускает каждый работающий плагин в собственной копии встроенного Service с `android:isolatedProcess="true"` через `bindIsolatedService`. У каждого плагина свой изолированный UID, отличный от UID Calamus и других плагинов. Требуется Android 10 или новее; на более старых версиях запуск запрещён. Небезопасного запасного режима нет.

Сессии Telegram, приватные файлы Calamus, разрешения основного приложения, сеть, камера, микрофон и контакты изолированному UID не предоставляются. В этом процессе не выполняется инициализация Telegram. Интерпретатор получает только выбранный проверенный пакет и встроенную стандартную библиотеку. Архив передаётся запечатанным файловым дескриптором; дополнительные пути к приватным файлам приложения не открываются.

Python выполняется через собственный узкий JNI-мост: только JSON-запрос к брокеру. Java interop и ctypes отсутствуют. Доверенные стандартные C-модули загружаются до исполнения плагина. Затем необратимый фильтр seccomp запрещает создание сетевых сокетов, fork/exec, ptrace, доступ к памяти других процессов и создание новых исполняемых отображений памяти. Добавление плагином сторонних `.so` не поддерживается. Android также не выдаёт изолированному UID INTERNET или разрешения устройства.

Брокер Calamus привязывает запрос к реальному каналу/UID и nonce запущенного плагина. Идентификатор из JSON не даёт выбрать чужое хранилище или разрешения. Все проверки возможностей и аккаунта/пользователя/чата выполняются в основном процессе после IPC. Изменение Python API или его внутренних объектов не выдаёт полномочий.

Изоляция не обещает защиту от всех уязвимостей Android, CPython и доверенного брокера. Плагин видит явно разрешённые данные и может их обрабатывать и сохранять в собственном хранилище. Подтверждение отправки означает согласие передать показанный текст выбранному адресату. Ограничения CPU/памяти не заменяют обновления ОС.

## Разрешения

При выборе `.plug` сначала открывается окно установки: название/версия/автор, полный список запрошенных возможностей и кнопки «Установить»/«Отмена» (при обновлении — «Обновить»). До согласия пакет только проверяется и хранится во временной копии; в список установленных он не попадает, код не запускается и разрешения не меняются.

Нажатие «Установить» выдаёт **все показанные разрешения** автоматически и включает плагин. Переключать каждую возможность вручную не нужно. Если запрошен доступ к аккаунтам/чатам, их выбирают в том же окне; без выбора данные аккаунта не предоставляются. Каждая отправка сообщения всё равно требует подтверждения. Расширенный экран доступа остаётся для последующего изменения/отзыва возможностей.

Обновления также требуют согласия. Отмена оставляет установленную версию, её данные и права без изменений. Подтверждение привязано к проверенной копии и SHA-256 пакета, используется один раз и истекает через 15 минут; повторное использование, изменение байтов и смена установленной версии после просмотра отклоняются. До четырёх пакетов могут ожидать подтверждения. Python API не предоставляет операций подтверждения/установки.

| Разрешение | Возможности |
| --- | --- |
| `storage` | Собственное JSON-хранилище, до 32 KiB |
| `notifications` | Подписанные именем плагина уведомления Toast |
| `accounts.read` | Только явно разрешённые аккаунты |
| `chats.read` | Только выбранные чаты разрешённых аккаунтов |
| `messages.read` | История/события сообщений выбранных чатов |
| `messages.send` | Запрос на отправку текста с отдельным подтверждением каждого сообщения |
| `ui` | Открытие разрешённого чата или информационного окна после вызова команды пользователем |
| `commands` | Регистрация команд, запускаемых пользователем |

Чтение серверной истории ограничено одним запросом в 10 секунд на плагин. Удаление и редактирование сообщений, выход из аккаунта, управление сессиями и произвольные Telegram RPC плагинам не предоставлены. API 3 добавляет строго ограниченное управление собственным online/offline для разрешённых аккаунтов. Платные сообщения и секретные чаты не поддерживаются. Никакой автоматической отправки без участия пользователя, включая автоответчики, эта версия не предоставляет.

JSON-запросы ограничены 64 KiB, глубиной 16 и 8192 токенами; разбор выполняется до обработки запроса в основном процессе.

Ограничения ресурсов: до 32 установленных и 4 работающих плагинов, архив до 2 MiB / 8 MiB распакованных данных / 128 записей; 240 вызовов моста в минуту, 60 записей хранилища в минуту, до 16 команд и 8 строк журнала. CPU-зависание плагина обнаруживается примерно за 15–20 секунд и приводит к остановке; ожидание подтверждения отправки ограничено 25 секундами. Авария одного изолированного процесса не завершает другие плагины. Дополнительно ограничены файловые дескрипторы (128) и потоки (32). Это ограничения ущерба и доступности, а не строгая квота памяти/CPU для каждого плагина.

`required_permissions` — необязательный список обязательных возможностей, являющийся подмножеством `permissions`. Менеджер проверяет их перед запуском; нормальная установка выдаёт весь показанный список. При последующем ручном изменении доступа обязательные возможности нельзя снять и одновременно запустить плагин. Для необязательных функций используйте `Context.has_permission`; решение о фактическом доступе принимает брокер.

Пример Hello Calamus доступен только в исходниках для разработчиков и тестах; в приложение не включается. Готовый плагин локального архива — `plugins/calamus_archive`, пакет `../Private-View.plug`.

## Пакет

```json
{
  "id": "ksnxdev.example",
  "name": "Example",
  "version": "1.0.0",
  "description": "A local command",
  "author": "ksnxdev",
  "api_version": 2,
  "permissions": ["storage", "commands"],
  "required_permissions": ["storage", "commands"],
  "events": ["app.foreground"],
  "settings": [
    {"key": "greeting", "title": "Greeting", "type": "string", "default": "Hello"}
  ]
}
```

`main.py`:

```python
from calamus_api import Plugin as BasePlugin

class Plugin(BasePlugin):
    def on_load(self, context):
        self.context = context
        context.register_command("local", "Local command")

    def on_command(self, name, arguments, chat):
        self.context.set("last_input", arguments)
        self.context.log(self.context.setting("greeting"))
```

Сборка пакета:

```bash
python3 tools/pack-plugin.py plugins/examples/hello ../hello.plug
```

Разрешённые файлы: `.py`, `.json`, `.txt`, `.md`, `.png`, `.jpg`, `.webp`. Обход путей, абсолютные пути и дубликаты записей запрещены. Обычная стандартная библиотека доступна в пределах разрешений изолированного UID. Дополнительные нативные Python-расширения, pip из сети и Android-библиотеки не поддерживаются. Для зависимостей нужны совместимые чистые Python-модули внутри пакета. Ресурсы пакета доступны только на чтение через загрузчик и виртуальные пути `/plugin/`. Постоянное состояние сохраняйте через `Context.get/set`.

## API

`Plugin`: `on_load(context)`, `on_unload()`, `on_event(name, payload)`, `on_command(name, arguments, chat)`. Остановка по ошибке/таймауту не гарантирует вызов `on_unload`; не полагайтесь на него для сохранения данных.

`Context`: `has_permission(permission)`, `get(key, default=None)`, `set(key, value)`, `setting(key)`, `log(text)`, `notify(text)`, `register_command(name, title)`, `accounts()`, `account(account_id)`. Настройки имеют типы `boolean`, `string`, `integer` и задаются схемой манифеста.

`AccountContext`: `chats(limit=50)`, `history(dialog_id, limit=20, offset_id=0)`, `send_message(dialog_id, text, reply_to=0)`, `open_chat(dialog_id)`, `show_dialog(title, text)`, `get(key, default=None)`, `set(key, value)`. Требуются разрешённый `account_id`, неизменившийся Telegram `user_id` и разрешённый `dialog_id`. Все проверки выполняет основной процесс Calamus. Метод отправки ожидает подтверждения; отмена возвращает исключение.

События: `app.started`, `app.foreground`, `app.background`, `account.changed`, `chat.opened`, `message.received`, `message.sent`, `message.failed`, `message.sending`, `message.updated`, `settings.changed`. События нужно перечислить в манифесте; данные аккаунта/чата фильтруются по области доступа, сообщения требуют `messages.read`. Непредусмотренные или недоступные события не доставляются.

Состояние хранится в `no_backup/isolated_plugins/` основного приложения. Старые установленные пакеты из `no_backup/python_plugins/installed` импортируются однократно как выключенные без разрешений. Старый тестовый режим с вымышленными аккаунтами и его экран удалены; его отдельные каталоги `sandbox_runtime` очищаются при запуске. Данные настоящего аккаунта автоматически в плагины не передаются.

## Проверка

`tools/test-plugins-emulator.sh` запускает реальные атакующие `.plug` во встроенных изолированных процессах без установленного внешнего модуля и проверяет ограничения файлов/Java/native/process/network, разделение хранилищ, запрет выдачи разрешений через мост, запрет отправки без доступа, отзыв сессий, области аккаунтов/чатов, повторную выдачу доступа при обновлении, зависание CPU, поддельное завершение и экраны в двух темах. Это техническая проверка без входа в Telegram; реальная доставка сообщений и работа с живым аккаунтом отдельно не проверены.

Источники устройства изоляции: [Android isolatedProcess](https://developer.android.com/guide/topics/manifest/service-element#isolated), [bindIsolatedService](https://developer.android.com/reference/android/content/Context#bindIsolatedService(android.content.Intent,int,java.lang.String,java.util.concurrent.Executor,android.content.ServiceConnection)), [CPython embedding](https://docs.python.org/3.11/extending/embedding.html). Контрольные суммы и происхождение runtime — `CalamusPlugins/vendor/python-runtime-verification.json`, лицензия — `CalamusPlugins/vendor/LICENSE.python`.

API 3 добавляет следующие возможности:

| Разрешение | Возможности |
| --- | --- |
| `messages.archive` | Запись и чтение собственного локального архива в выбранных чатах; дополнительно требуется messages.read |
| `messages.menu` | До 8 именованных действий в контекстном меню сообщения; дополнительно требуется messages.read |
| `presence.control` | Управление собственным online/offline в разрешённых аккаунтах, без изменения правил приватности |
| `presence.read` | Доступный клиенту статус пользователя в выбранном личном чате, без обхода серверной приватности |

`Context.register_message_action(name, title)` регистрирует действие. Вызов из меню доставляет `message.action` с полями `action`, `message`, `account_id`, `user_id`, `dialog_id` только выбранному плагину; контекст и разрешения перепроверяются. Вызов даёт короткое разрешение показать UI, как и пользовательская команда. `message.deleted` содержит только ID уже сохранённых версий в доступной области. ID каналов отделяются от глобальных ID личных чатов.

`AccountContext.archive_record(message)`, `archive_query(dialog_id, message_id=..., version_id=..., deleted_only=..., limit=..., offset=...)`, `show_archive(dialog_id, message_id=0, deleted_only=False)`, `set_ghost(enabled)`, `presence(dialog_id)` работают только через брокер. Просмотр архива требует ui + messages.archive + messages.read и действия пользователя. Запрос полного текста возвращает одну версию по version_id, списки возвращают короткие превью. SQLite ограничена 16 МиБ и 20000 версиями; исходные сообщения/медиа с TTL не передаются в новые архивные события.

Архив имеет отдельную очередь хранения, чтобы синхронный вызов Python не блокировал управляющую очередь плагина. Доступ перепроверяется перед операцией и выдачей результата. Удаление пакета стирает его архив, выход стирает записи конкретного Telegram user_id. Любое управление присутствием привязано к настоящему isolation_session и освобождается при отзыве этой сессии.

В Calamus 71370 на экранах установки и доступа есть «Выбрать все» / «Снять выделение» для текущего списка доступных чатов всех активных аккаунтов. Можно оставить отдельные чаты невыбранными. Выбор вступает в силу только при подтверждении установки или «Сохранить и включить». Хранятся явные разрешения по account_id/user_id/dialog_id, без автоматического доступа к будущим чатам; предел — 4096 чатов на плагин. Список больше не обрезается до 100 чатов аккаунта.

В Calamus 71380 карточка плагина с булевой настройкой `ghost` и возможностью `presence.control` показывает быстрый переключатель режима призрака. Он управляет режимом через штатное событие settings.changed и показывает собственные активные leases плагина для разрешённых аккаунтов. Состояние другого плагина не выдаётся за состояние текущего. При отсутствии разрешения, активного аккаунта или работающего плагина переключатель отключён. Та же проверка фактического состояния используется на экране параметров плагина. Private View 1.1.0 поддерживается без обновления пакета.

В Calamus 71390 пункт «Просмотреть удалённые» остаётся видимым в меню обычного облачного чата даже без активного провайдера архива. После ожидания загрузки списка плагинов клиент либо открывает разрешённый архив, либо показывает подсказку о Private View и доступе к этому чату с переходом к плагинам. Проверка разрешений и сессии для чтения архива сохраняется.

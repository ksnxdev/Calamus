# Локальный эмулятор Calamus

Проверка меню сообщения в стиле iOS: `CALAMUS_PLUGIN_CHECK_MODE=iosmenu ./tools/test-archive-emulator.sh`. Использует синтетический аккаунт и сообщения в памяти, временно отключает сеть. Проверяет удержание сообщения, расположение реакций над превью, обе темы, входящие/исходящие сообщения, системное и программное размытие, совместную и раздельную прокрутку, оба способа закрытия и возврат стандартного меню. Ресурсы реакций в этом тесте подменены; загрузка анимаций с сервера не проверяется. Снимки — `ios-message-menu-*`, `ios-message-dismiss-*`. Доступность переключателя без доната проверяется `./tools/test-settings-emulator.sh`.

Проверка стартового экрана и ввода номера без запроса авторизации: `./tools/test-startup-emulator.sh`. Проверяет обе темы, подпись Powered by Cherrygram, переход к номеру и контраст подсказки. Необязательные разрешения телефона отклоняются; локально сохранённые данные формы восстанавливаются после теста. Снимки: `startup-intro-*`, `startup-login-*`.

В Calamus 71400 архивная проверка дополнена белым текстом реального поля ввода в тёмной теме, Unicode-превью на границе эмодзи и массовым удалением при 4096 областях доступа и 1000 идентификаторах. Итоги общей проверки: `CALAMUS_BUG_AUDIT.md`.

Виртуальное устройство `Calamus_API35`: Android 15 / API 35, x86_64, 720 × 1600, плотность 320 dpi, 1536 MiB RAM, 2 ядра, KVM и программный графический backend. Его данные находятся в `~/.android/avd/Calamus_API35.avd`. Другие виртуальные устройства не изменяются.

```bash
./tools/emulator.py start
JAVA_HOME=/usr/lib/jvm/java-21-temurin ./tools/build-emulator.sh --console=plain
./tools/emulator.py install
./tools/emulator.py screenshot --output ../emulator/screenshots/calamus.png
```

Команды работают из `Cherrygram/`. Путь SDK читается из `local.properties`. Скрипт устанавливает корректные `ANDROID_HOME` и `ANDROID_SDK_ROOT` для запуска эмулятора. Нужны установленный emulator и образ `system-images;android-35;default;x86_64`; в текущем окружении они уже имеются. `./tools/emulator.py setup` создаёт устройство, если его нет.

Сборка с `-Pcalamus.emulator=true` использует x86_64 и имя `Calamus-Emulator-12.10.6-debug-universal.apk`. Она предназначена для эмулятора и не заменяет готовый APK телефона в родительской папке. Без этого параметра сборка остаётся ARM64 + ARMv7. Исходники и собственные API-реквизиты приложения общие для обеих сборок. Первичная компиляция нативных библиотек x86_64 занимает несколько минут; последующие сборки используют кеш.

По умолчанию эмулятор работает без окна. Управлять им можно через ADB, сохраняя скриншоты. Для интерактивного окна сначала остановить запущенный экземпляр:

```bash
./tools/emulator.py stop
./tools/emulator.py start --window
```

Проверить состояние и остановить:

```bash
./tools/emulator.py status
./tools/emulator.py stop
```

ADB-адрес — `emulator-5580`. Скрипт установки всегда указывает этот адрес и не обращается к подключённым телефонам. Журнал эмулятора — `../emulator/android-emulator.log`. Скриншоты по умолчанию сохраняются в `../emulator/screenshots/`.

У эмулятора отдельное хранилище приложения. Без входа доступны проверка запуска, стартового экрана и ввода номера. Для проверки настоящих чатов и экранов аккаунта нужен вход в отдельный тестовый Telegram-аккаунт. Учётные данные и сессии с телефона или Telegram Desktop автоматически не переносятся.

Проверено в текущем окружении: установка APK x86_64, холодный запуск, стартовый экран в светлой и тёмной темах, переход к вводу номера и серая маска незаполненных цифр. После этих действий журнал сбоев пуст. Результаты и скриншоты — в `../emulator/verification.json` и `../emulator/screenshots/`. Вход в аккаунт не выполнялся.

Изолированная проверка панелей и переключателя внешнего вида без аккаунта:

```bash
./tools/test-panels-emulator.sh
```

Перед запуском нужно установить свежую сборку для эмулятора. Тестовый APK подписывается локальным debug-ключом и предназначен только для `Calamus_API35`. Он проверяет реальные компоненты заливки, открывает экран Appearance, нажимает переключатель и восстанавливает настройку. Скриншоты `panel-render-*.png` и `appearance-translucency-*.png` сохраняются в папке снимков эмулятора.

Проверка системы Python-плагинов на установленной сборке эмулятора:

```bash
./tools/test-plugins-emulator.sh
```

Проверяет реальные атакующие плагины во встроенных сервисах `isolatedProcess`. Установки второго APK нет. Тест проверяет разные UID, отсутствие INTERNET, запреты файлов/Java/native/process/network, раздельное хранилище, разрешения и области чатов, отзыв сессий, Unicode, обновление пакета, watchdog CPU и экраны в обеих темах. Telegram-аккаунт не используется.

Обычная сборка телефона имеет `debuggable=false`; сборка с `calamus.emulator=true` допускает instrumentation. Встроенная изоляция обязательна в обеих сборках. Старые тестовый режим и внешний модуль удалены. Логи текущей проверки и снимки — `../emulator/`.

Проверка файловых кнопок с реальным RadialProgress2/MediaActionDrawable и подложенным градиентом пузыря:

```bash
./tools/test-files-emulator.sh
```

Проверяются входящие/исходящие сообщения, обычное/нажатое состояния и download/cancel/file в обеих темах. Сверяются фактические пиксели значков и контраст. Снимки — `file-controls-light.png`, `file-controls-dark.png`.

Проверка предварительного подтверждения установки и обновления через интерфейс:

```bash
CALAMUS_PLUGIN_CHECK_MODE=example ./tools/test-plugins-emulator.sh
```

Проверяются отсутствие установки/запуска до согласия, автоматическая выдача всего показанного списка, отмена установки и обновления, неизменность старой версии, привязка к точным байтам, одноразовое подтверждение и отказ устаревшего просмотра. Проверяются файловый импорт, обновление старой версии и обе темы. Пример находится только в тестовых ресурсах; в приложение он не включается. Реального Telegram-аккаунта нет.

Проверка настроек Calamus, канала, меню плагинов и выбора цвета в обеих темах без аккаунта:

```bash
./tools/test-settings-emulator.sh
```

Проверяются блокировка ручного выбора при системном цвете, применение и отмена цвета, сохранение при повторном открытии и восстановление системной палитры. Снимки — `calamus-settings-*`, `calamus-about-*`, `calamus-plugins-*`, `calamus-color-*`.

Проверка подписей навигации и заголовка плагинов:

```bash
./tools/test-navigation-emulator.sh
```

Проверяются реальные компоненты нижней панели без Telegram-аккаунта: аватар, чаты и поиск с подписями и без них, общая базовая линия, отсутствие обрезки текста, центры значков и доступные названия. Переключатель проверяется через экран внешнего вида, заголовок — на экране плагинов. Проверки и снимки выполняются в светлой и тёмной темах.

Проверка Private View и локального отображения удалённых сообщений:

```bash
./tools/test-archive-emulator.sh
```

Использует временные данные в памяти эмулятора без Telegram-авторизации и временно включает авиарежим. Проверяет миграцию старого архива, Unicode-поиск по всей базе за пределами первой страницы, сообщения/правки/удаления через NotificationCenter, серию 130 сообщений, отсутствие остановки на asyncio tick, сохранение удалённого сообщения в ChatActivity, загрузку из базы после очистки представления, серый цвет и метку в реальном ChatMessageCell, историю из контекстного меню удалённого сообщения, пункт меню чата, поиск через интерфейс и скрытие записей при отключении плагина. Снимки `inline-deleted-*`, `deleted-menu-*`, `deleted-search-*`, `archive-*` создаются в светлой и тёмной темах. Поведение реального Telegram-сервера такой тест не подтверждает.

Проверка массового выбора чатов: `./tools/test-selection-emulator.sh`. На отдельном эмуляторе без авторизации временно используются два аккаунта в памяти и 137 диалогов. Проверяются оба экрана, выбор/снятие/частичный выбор, сохранение только после подтверждения и разделение аккаунтов. Сеть временно отключается, настройки и данные в памяти восстанавливаются; снимки — `select-all-install-*`, `select-all-access-*`.

Проверка быстрого переключателя призрака: `./tools/test-ghost-emulator.sh`. Использует настоящий Private View и native host, два синтетических аккаунта только в памяти, временный авиарежим, проверку on/off, сохранения настройки, совместимости с командами, переключателя в параметрах и отсутствия доступа после отзыва presence.control. Снимки `ghost-menu-*` сохраняются для обеих тем. Реальная видимость статуса через Telegram-сервер не проверяется.
